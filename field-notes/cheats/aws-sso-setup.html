Setting Up AWS SSO (Identity Center)

Complete workflow for configuring AWS IAM Identity Center with a single identity, permission sets, and AWS CLI SSO integration.

1Create an Identity Center Instance

Navigate to IAM Identity Center in the AWS Console (or use the CLI).

# Enable Identity Center (requires Organizations)
aws sso-admin create-instance \
  --name "my-org-sso"
Note: Identity Center requires AWS Organizations. If you're on a standalone account, you'll be prompted to create an organization first.

After creation, note your SSO Start URL and SSO Region — you'll need both for CLI configuration.

2Configure a Single Identity

Create a user in the Identity Center directory:

  1. Go to Users → Add user
  2. Enter email, first name, last name
  3. The user receives an email to set their password
  4. Optionally enable MFA (recommended for SOC2)
# Verify the user was created
aws identitystore list-users \
  --identity-store-id d-1234567890

3Create and Assign Permission Sets

Permission sets define what a user can do when they assume a role in an AWS account.

# Create a permission set
aws sso-admin create-permission-set \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --name "DevAccess" \
  --session-duration PT8H

Attach managed policies for the minimum access needed:

# CLI access — allows basic AWS CLI operations
aws sso-admin attach-managed-policy-to-permission-set \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --permission-set-arn arn:aws:sso:::permissionSet/ssoins-1234567890/ps-abcdef \
  --managed-policy-arn arn:aws:iam::aws:policy/ReadOnlyAccess

# SSM access — required for session manager
aws sso-admin attach-managed-policy-to-permission-set \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --permission-set-arn arn:aws:sso:::permissionSet/ssoins-1234567890/ps-abcdef \
  --managed-policy-arn arn:aws:iam::aws:policy/AmazonSSMFullAccess

# EC2 access — for launching/managing instances
aws sso-admin attach-managed-policy-to-permission-set \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --permission-set-arn arn:aws:sso:::permissionSet/ssoins-1234567890/ps-abcdef \
  --managed-policy-arn arn:aws:iam::aws:policy/AmazonEC2FullAccess

# S3 access — scoped to specific buckets via inline policy (see sub-note)
aws sso-admin put-inline-policy-to-permission-set \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --permission-set-arn arn:aws:sso:::permissionSet/ssoins-1234567890/ps-abcdef \
  --inline-policy '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket", "s3:PutObject"],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    }]
  }'

Then assign the permission set to the user for a target account:

aws sso-admin create-account-assignment \
  --instance-arn arn:aws:sso:::instance/ssoins-1234567890 \
  --target-id 123456789012 \
  --target-type AWS_ACCOUNT \
  --permission-set-arn arn:aws:sso:::permissionSet/ssoins-1234567890/ps-abcdef \
  --principal-type USER \
  --principal-id <user-id-from-identity-store>

4Configure AWS CLI for SSO

# Run the guided SSO configuration
aws configure sso

# It will prompt for:
#   SSO session name: my-sso
#   SSO start URL:    https://d-1234567890.awsapps.com/start
#   SSO region:       us-east-1
#   SSO registration scopes: sso:account:access

This creates entries in ~/.aws/config. Your resulting profile looks like:

[profile my-dev]
sso_session = my-sso
sso_account_id = 123456789012
sso_role_name = DevAccess
region = us-east-1

[sso-session my-sso]
sso_start_url = https://d-1234567890.awsapps.com/start
sso_region = us-east-1
sso_registration_scopes = sso:account:access

Log in and verify:

# Authenticate via browser
aws sso login --profile my-dev

# Verify identity
aws sts get-caller-identity --profile my-dev
▶ Identity Policies

The SSO user's permissions come from the permission set, not from IAM policies attached to an IAM user. There is no IAM user created — SSO uses temporary STS credentials.

Key concepts:

  • Identity Store: Where users/groups live (managed by Identity Center)
  • Permission Set: A collection of policies that map to an IAM role in each assigned account
  • Account Assignment: Links a user/group + permission set to an AWS account

When a user logs in via SSO, they assume a role like AWSReservedSSO_DevAccess_abcdef1234 in the target account.

▶ Permission Set Structure

A permission set can contain:

  • AWS Managed Policies: Pre-built policies like AmazonSSMFullAccess
  • Customer Managed Policies: Policies you've created in IAM
  • Inline Policy: A single JSON policy embedded in the permission set
  • Permissions Boundary: An upper limit on what the resulting role can do

Best practice: use managed policies for broad access categories, inline policies for scoping (e.g., restricting S3 to specific buckets).

▶ SOC2-Friendly Policy Minimums

For SOC2 compliance, follow least-privilege principles:

  • No wildcard resources: Always scope Resource to specific ARNs
  • No * actions: Use specific actions like ssm:StartSession instead of ssm:*
  • Session duration: Keep under 8 hours; 4 hours is better
  • MFA required: Enable MFA in Identity Center settings
  • Audit trail: CloudTrail captures all SSO login events automatically

Minimum viable policy set for a developer:

# Instead of AmazonSSMFullAccess, scope to:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ssm:StartSession",
        "ssm:TerminateSession",
        "ssm:ResumeSession",
        "ssm:DescribeSessions",
        "ssm:GetConnectionStatus"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeSecurityGroups",
        "ec2:DescribeSubnets",
        "ec2:DescribeVpcs"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    }
  ]
}
