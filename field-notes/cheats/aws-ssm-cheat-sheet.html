SSM Cheat Sheet

AWS CLI workflows for SSM sessions, port forwarding, RDS tunneling, and S3 operations. SSO is assumed to be already configured.

Prerequisites: AWS CLI v2, Session Manager plugin installed, SSO profile configured, bastion instance running.

Log Into SSO

# Authenticate (opens browser)
aws sso login --profile my-dev

# Verify identity
aws sts get-caller-identity --profile my-dev

Start an SSM Session (Shell Access)

# Connect to the bastion
aws ssm start-session \
  --target i-0abc123def456 \
  --profile my-dev

Internal Website Tunnel (Port Forwarding)

Forward a local port to a remote host accessible from the bastion. Useful for internal dashboards, admin panels, or services behind the VPC.

# Forward local:8080 to internal-app.private:80 via the bastion
aws ssm start-session \
  --target i-0abc123def456 \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{
    "host": ["internal-app.private"],
    "portNumber": ["80"],
    "localPortNumber": ["8080"]
  }' \
  --profile my-dev

Then open http://localhost:8080 in your browser.

MariaDB Tunnel to EC2

If MariaDB is running directly on an EC2 instance:

# Forward local:3306 to the EC2 instance's MariaDB (localhost:3306)
aws ssm start-session \
  --target i-0abc123def456 \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{
    "portNumber": ["3306"],
    "localPortNumber": ["3306"]
  }' \
  --profile my-dev

Connect with your database client:

# Connect via the tunnel
mysql -h 127.0.0.1 -P 3306 -u dbuser -p

RDS Tunnel Using the Bastion

For an RDS instance that's only accessible within the VPC, use the bastion as a jump host:

# Forward local:3306 to RDS endpoint via bastion
aws ssm start-session \
  --target i-0abc123def456 \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{
    "host": ["my-db.cluster-abc123.us-east-1.rds.amazonaws.com"],
    "portNumber": ["3306"],
    "localPortNumber": ["3306"]
  }' \
  --profile my-dev

Connect with your database client:

# Connect to RDS through the tunnel
mysql -h 127.0.0.1 -P 3306 -u admin -p

# Or with a GUI client, use:
#   Host: 127.0.0.1
#   Port: 3306
#   User: admin
Tip: If port 3306 is already in use locally, change localPortNumber to something else (e.g., 13306) and connect to 127.0.0.1:13306.

Listing and Navigating S3 Files

# List all buckets
aws s3 ls --profile my-dev

# List contents of a bucket
aws s3 ls s3://my-bucket/ --profile my-dev

# List with human-readable sizes
aws s3 ls s3://my-bucket/path/ --human-readable --summarize --profile my-dev

# Recursive listing
aws s3 ls s3://my-bucket/ --recursive --profile my-dev

Downloading Files from S3 to EC2

Once connected to the bastion via SSM session:

# Download a single file
aws s3 cp s3://my-bucket/path/file.csv /tmp/file.csv

# Download a directory
aws s3 cp s3://my-bucket/path/ /tmp/data/ --recursive

# Sync a directory (only downloads changed files)
aws s3 sync s3://my-bucket/path/ /tmp/data/

# Download with a filter
aws s3 cp s3://my-bucket/logs/ /tmp/logs/ --recursive --exclude "*" --include "*.gz"
Note: S3 commands on the bastion use the EC2 instance role, not your SSO profile. The bastion's role must have S3 permissions for the target bucket.
▶ Required EC2 IAM Role

The bastion EC2 instance needs this role attached via an instance profile:

Role: bastion-ssm-role
Managed Policies:
  - AmazonSSMManagedInstanceCore

Inline Policy (bastion-s3-access):
  s3:GetObject, s3:ListBucket, s3:PutObject
  scoped to specific bucket ARNs

The EC2 role does not need SSO, STS, or RDS IAM policies for standard operations.

▶ Minimum SOC2-Friendly Policies

For SOC2, scope all permissions tightly:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "SSMSessions",
      "Effect": "Allow",
      "Action": [
        "ssm:StartSession",
        "ssm:TerminateSession",
        "ssm:ResumeSession"
      ],
      "Resource": [
        "arn:aws:ec2:us-east-1:123456789012:instance/i-0abc*",
        "arn:aws:ssm:*:*:document/AWS-StartSSHSession",
        "arn:aws:ssm:*:*:document/AWS-StartPortForwardingSession",
        "arn:aws:ssm:*:*:document/AWS-StartPortForwardingSessionToRemoteHost"
      ]
    },
    {
      "Sid": "S3Scoped",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-bucket",
        "arn:aws:s3:::my-bucket/*"
      ]
    },
    {
      "Sid": "DescribeOnly",
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ssm:DescribeInstanceInformation",
        "ssm:DescribeSessions"
      ],
      "Resource": "*"
    }
  ]
}
▶ Required SSO Identity Policies

Your SSO permission set needs these actions for SSM workflows:

  • ssm:StartSession — start a shell or port-forward session
  • ssm:TerminateSession — cleanly end sessions
  • ssm:ResumeSession — reconnect to a dropped session
  • ssm:DescribeSessions — list active sessions
  • ssm:DescribeInstanceInformation — check if instances are SSM-managed
  • ec2:DescribeInstances — look up instance metadata

For S3 operations from your local machine (not the bastion), add scoped S3 actions to the permission set as well.

▶ Local Environment Configuration

Install the Session Manager Plugin

# macOS
brew install --cask session-manager-plugin

# Linux (Debian/Ubuntu)
curl "https://s3.amazonaws.com/session-manager-downloads/plugin/latest/ubuntu_64bit/session-manager-plugin.deb" -o session-manager-plugin.deb
sudo dpkg -i session-manager-plugin.deb

# Verify
session-manager-plugin --version

AWS CLI Config (~/.aws/config)

[profile my-dev]
sso_session = my-sso
sso_account_id = 123456789012
sso_role_name = DevAccess
region = us-east-1

[sso-session my-sso]
sso_start_url = https://d-1234567890.awsapps.com/start
sso_region = us-east-1
sso_registration_scopes = sso:account:access

Shell Alias (optional)

# Add to ~/.zshrc or ~/.bashrc
alias bastion='aws ssm start-session --target i-0abc123def456 --profile my-dev'
alias rds-tunnel='aws ssm start-session --target i-0abc123def456 --document-name AWS-StartPortForwardingSessionToRemoteHost --parameters '\''{"host":["my-db.cluster-abc123.us-east-1.rds.amazonaws.com"],"portNumber":["3306"],"localPortNumber":["3306"]}'\'' --profile my-dev'
▶ EC2 Configuration

Bastion instance requirements:

  • AMI: Amazon Linux 2023 (SSM Agent pre-installed)
  • Instance type: t3.micro or t3.nano
  • Public IP: None
  • Key pair: None (SSM only)
  • IMDSv2: Required (HttpTokens=required)
  • IAM Role: bastion-ssm-role with AmazonSSMManagedInstanceCore

Verify SSM Agent Status

# From your local machine
aws ssm describe-instance-information \
  --filters "Key=InstanceIds,Values=i-0abc123def456" \
  --query "InstanceInformationList[0].PingStatus" \
  --output text --profile my-dev

# Should return: Online

Restart SSM Agent (if needed)

# If you have shell access via another method:
sudo systemctl restart amazon-ssm-agent
sudo systemctl status amazon-ssm-agent
